The module is a self-contained Supabase project rooted at `supabase/` with a single project ID (`tbs-lpdp`) declared in `config.toml`. Database evolution is split across versioned SQL files applied in order: `schema.sql` (base v1 tables for packages/subtests/questions/attempts plus RLS), `schema_v2_reports.sql`, `schema_v3.sql`, and `schema_v4_maintenance_mode.sql`, with `maintenance.sql` and `backfill_v3_1_statistics.sql` providing post-migration housekeeping. All client mutations are gated through stored procedures/RPCs — the schema header explicitly forbids direct table writes from clients. A Deno edge function under `functions/question-report-digest/` exposes an HTTP POST endpoint that claims a digest run via the `claim_question_report_digest` RPC, renders HTML/text payloads via `render.ts`, sends them through the Resend API, and records success or failure via `complete_question_report_digest` / `fail_question_report_digest` RPCs. Secrets (automation key, admin key, Resend key, email addresses) are read from `SUPABASE_SECRET_KEYS` JSON or environment variables; JWT verification is disabled in `config.toml` so callers authenticate by passing an `apikey` header matching the automation key. The `.temp/` directory holds runtime linkage metadata (project ref, versions) used by the Supabase CLI.
