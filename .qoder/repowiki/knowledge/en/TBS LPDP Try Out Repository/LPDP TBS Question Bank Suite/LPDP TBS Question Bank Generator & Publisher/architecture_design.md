The module is organized as a flat collection of single-purpose CLI scripts plus a shared `common.py` library. Each computable question type lives in its own script (`deret_angka.py`, `deret_huruf.py`, `aritmetika.py`, `aljabar.py`, `kecukupan_data.py`, `kecukupan_data_predikat.py`, `peluang_kombinatorik.py`) and imports from `common` for blueprint constants, schema loading, `make_question` / `write_question` helpers, and number formatting — dependency direction is strictly one-way: generators → common. `figures.py` is a separate SVG builder with a registry pattern (`FIGURES`, `SHARED_FIGURES`) where each figure has a builder returning a `Drawing` dataclass; it can regenerate all SVGs, diff them against disk (`--check`), or link questions to their images (`--link`). `validate_bank.py` is the CI gate: it loads `questions/schema.json`, walks every package under `BANK_DIR`, checks JSON schema conformance, path-to-id consistency, passage/image constraints per type, duplicate/gap-free numbering, and optional strict blueprint counts. `push_to_supabase.py` is the publisher: it loads a package manifest, uploads content-addressed images to Supabase Storage, builds a canonical JSON-B payload whose hash mirrors PostgreSQL's jsonb text rendering, and calls the `publish_package_release` RPC atomically; it supports `--dry-run` without credentials and `--all` to publish every package found. All scripts accept `--seed` for reproducibility and `--bank-dir` to target a scratch directory instead of the repo's `questions/bank`.
