Entry point `main.tsx` mounts a `<StrictMode>` root that renders `App.tsx`, which configures `HashRouter` (chosen so deep links survive refresh on GitHub Pages without rewrite rules) and wraps routes in `MaintenanceGate` + `HumanVerificationGate` guards that are folded away when `IS_OFFLINE_APP` is true. Routes map to three page components under `pages/`: `HomePage` (package catalogue + attempt history), `AttemptPage` (timed exam flow), and `ReviewPage` (post-attempt solutions). All pages share layout chrome via `components/AppShell.tsx`, which injects the masthead, `MenuBar`, `FeedbackFooter`, and optional chrome hiding during exams. Cross-cutting concerns live in `lib/`: `config.ts` exposes build-time flags (`VITE_OFFLINE`, `VITE_SUPABASE_*`, `VITE_TURNSTILE_SITE_KEY`) and shared constants; `api.ts` lazily dynamic-imports either `localApi` (mock/offline engine) or `supabaseApi` based on env, caching one implementation and auto-reloading on chunk-load errors; `types.ts` defines the shared `ExamApi` contract. State is kept local to pages plus a small `contexts/MaintenanceContext.ts` and `hooks/useTick.ts` for timers. The HTML shell in `web/index.html` carries SEO metadata (Open Graph, Twitter Card, JSON-LD schema.org WebApplication + FAQPage) and static assets under `public/` (favicon, sitemap, cover images). Three build flavors coexist — web production, mock, and offline Tauri app — selected at compile time via Vite `import.meta.env` so each bundle drops unused code (Supabase client, answer keys, Turnstile).
