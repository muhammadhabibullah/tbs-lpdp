Two layers cooperate around a single source of truth — the `questions/bank/` directory on disk. `bank-reader.ts` is the core compiler: it walks package directories under `bankDir`, reads each package's `package.json` and per-subtest `.json` questions, computes per-file revision numbers from `git log` (falling back to file mtimes when no history exists), and emits the `{ packages, questions }` shape consumed by the exam engine, with images either inlined as data URIs or served via an image cache map keyed by `<package>/<sha256>/<file>`. `bank-artifact.ts` wraps `readBank` to produce the published pair — an immutable `bank-<digest>.json` (SHA-256 of the JSON) and a small mutable `manifest.json` pointing at it — used by both CI publishing and the offline app bundle. Two Vite plugins consume this reader: `mock-bank-plugin.ts` (`apply: 'serve'`) mounts `/__mock/bank.json` and `/__mock/image/...` so the SPA runs against live bank files during development; `bank-asset-plugin.ts` emits the compiled manifest + bank files as assets in `generateBundle()` for the offline flavor and serves them under `/bank` in `configureServer()`. The `scripts/` layer provides standalone Node entry points: `build-bank.ts` invokes the Python validator (`validate_bank.py`) then writes the artifact pair to `dist/bank`, enforcing full git history for reproducibility; `patch-android-signing.ts` idempotently rewrites `src-tauri/gen/android/app/build.gradle.kts` to inject a release `signingConfigs` block that reads keystore credentials from `keystore.properties`, failing loudly if the Tauri template changes.
