The repository is organized as a multi-project monorepo where each child owns one deployment plane or data asset: `web/` builds the SPA (and Tauri shell) in three flavors — web production against Supabase, dev mock off Git files, and offline app with a bundled bank — selected at compile time via Vite defines so dead branches are provably eliminated. `questions/bank/` is the canonical source of truth for exam content; `questions/generator/` produces deterministic items and validates them, while `web/vite/bank-artifact.ts` compiles the bank into `manifest.json` + `bank-<digest>.json` artifacts consumed by both the GitHub Pages site and the Tauri release. `supabase/` holds the authoritative schema, RLS policies, RPC functions, migrations, and a Deno edge function that emails daily report digests; the SPA calls these RPCs for all trusted grading and timing logic. `agents_config/` and `docs_and_scripts/` provide cross-cutting AI-assisted authoring skills and version bumping scripts used when modifying questions or releases. CI workflows in `.github/workflows/` orchestrate the full pipeline: validate+build bank artifact, deploy SPA to GitHub Pages, and publish signed Tauri installers/APKs.
