The module is organized as a flat data asset: `questions/schema.json` defines a JSON Schema (draft 2020-12) describing the shape of every question record — mandatory fields (`id`, `package`, `subtest`, `number`, `type`, `question_text`, `image`, `passage`, `options`, `correct_option`, `explanations`, `difficulty`, `source`, `verified`) with strict enums for `subtest` (`verbal`, `kuantitatif`, `pemecahan_masalah`), `type` (20 question-type tokens), five-option arrays keyed A–E, and an image path pattern. The `questions/sample/` directory mirrors the three subtests as sibling folders, each containing numbered `.txt` files (e.g., `verbal/1.txt`, `kuantitatif/1.txt`, `pemecahan_masalah/1.txt`) written in Indonesian plain text with a fixed layout: a header line naming the subtest, then questions numbered sequentially, each followed by five choices labeled A–E and a `Jawaban : <letter>` line indicating the correct option. The schema enforces structural validity while the human-readable `.txt` files serve as source material consumed by a loader (referenced elsewhere as `validate_bank.py` / `common.py`) that parses them into the validated JSON structure.
